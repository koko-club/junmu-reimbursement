# 在线报销系统：用户认证与个人历史设计

## 1. 目标

在已经验证可用的差旅报销表单、Excel 生成和 PDF 转换功能上，增加：

- 一次性初始管理员设置。
- 普通用户自助注册和管理员审批。
- 管理员和普通用户的单会话登录。
- 用户个人报销 Excel/PDF 历史。
- 30 天回收站。
- Mac 本机开发调试和群晖 DS925+ Docker 部署。

实施将在 `/Users/koko/Documents/Codex/在线报销系统` 中进行。现有项目
`/Users/koko/Documents/Codex/其他/reimbursement_form_app_20260903` 只作为源版本，不直接修改，以便随时回退。

## 2. 非目标

- 不迁移旧项目 `generated/` 内无法确认归属的文件。
- 不允许管理员通过应用查看或下载普通用户的报销文件。
- 不开放外网，不在首版集成短信、邮件或第三方单点登录。
- 不重写已验证的 Excel 填充和 PDF 排版规则。
- 不允许普通用户在报销表单中修改账号档案中的姓名和部门。

## 3. 方案选择

已比较三种方案：

1. 保留 Python `ThreadingHTTPServer`，添加 SQLite 和聚焦的认证、存储模块。
2. 迁移到 Flask 后再实现相同功能。
3. 改为前后端分离和独立数据库服务。

选择方案 1。该方案最大限度保留当前已测试的生成逻辑，减少与认证无关的迁移风险。认证不依赖客户端判断，所有资源权限都在服务端执行。

## 4. 系统架构

应用保留单容器、单进程的简单部署形式，但将职责分开：

- 服务器入口：启动 HTTP 服务、路由请求、生命周期和每日清理任务。
- 数据库层：SQLite 连接、事务、模式迁移和查询。
- 认证层：密码哈希、登录会话、CSRF 和当前用户解析。
- 用户服务：注册、审批、拒绝、停用、启用、档案修改和密码重置。
- 报销服务：生成记录、归属检查、历史、下载和回收站。
- 生成器：复用现有 Excel 填充、图片处理和 LibreOffice PDF 转换。
- 静态前端：登录/注册、普通用户和管理员三类界面。

现有模板和生成规则将复制到新项目，并用回归测试锁定现有行为。

## 5. 持久化数据

### 5.1 users

- `id`：数值主键。
- `username`：显示用户名。
- `username_key`：归一化后用于唯一索引，英文字母忽略大小写。
- `password_hash` / `password_salt` / `password_params`：`scrypt` 密码材料。
- `real_name` / `department`：用户档案。
- `role`：`admin` 或 `user`。
- `status`：`pending`、`active` 或 `disabled`。
- `must_change_password`：临时密码登录后的强制改密标记。
- `created_at` / `approved_at` / `updated_at`：UTC 时间。

待审批用户保存在同一张表。拒绝时在事务内删除记录，用户名随即释放。已批准用户不提供删除操作。

### 5.2 sessions

- `token_hash`：会话令牌的 SHA-256 哈希，作为主键。
- `user_id`：唯一外键，从数据库层确保每个账号只有一个会话。
- `csrf_token`：修改类请求的随机 CSRF 校验材料。
- `created_at` / `expires_at`：创建时间和最长 7 天的绝对过期时间。

数据库不保存原始 Cookie 令牌。登录路由先调用 `UserService.authenticate()`，再将返回的 `User` 认证快照传给 `SessionService.issue(authenticated_user)`；不提供裸 `user_id` 签发路径。签发在同一个 `BEGIN IMMEDIATE` 事务内要求账号仍为 `active`，且 `password_version` 与 `status_version` 同时匹配认证快照，然后删除该用户的旧会话并插入新会话。密码修改、管理员重置、停用或停用后重新启用都会改变版本，旧认证快照不得重新签发会话。

### 5.3 reimbursements

- `id`：随机记录 ID，用于内部存储和路由。
- `user_id`：所属普通用户 ID，必须参与每个资源查询。
- `reimbursement_date`：用户选择的报销日期，允许为空。
- `display_name`：历史列表中的文件显示名。
- `xlsx_path` / `pdf_path`：由服务端生成的受控相对路径。
- `created_at` / `deleted_at`：UTC 时间；`deleted_at` 为空表示正常历史。

实际文件放在 `/data/users/<user_id>/<record_id>/`。服务端将数据库路径解析到 `/data` 后，还必须校验结果仍在该记录目录内。

### 5.4 app_settings 和 schema_migrations

`app_settings` 保存 `setup_complete`，首个管理员创建成功后在同一事务中设为真。后续即使访问已知路径，也不再接受初始化。

`schema_migrations` 记录数据库版本。容器启动时在事务中逐版迁移。

### 5.5 SQLite 运行方式

- 开启外键、WAL 和繁忙等待。
- 每个 HTTP 请求使用自己的数据库连接，不在线程之间共享连接。
- 事务只包含必要的数据库更新，不在事务中等待 LibreOffice。
- 所有数据库时间保存为 UTC，界面按 Asia/Shanghai 显示。

## 6. 认证与用户流程

### 6.1 初始管理员

1. 如果 `setup_complete` 为假，访问应用时跳转一次性设置页。
2. 提交时使用排他事务再次检查设置状态，防止并发创建两个初始管理员。
3. 创建管理员和设置 `setup_complete` 必须同时成功或回滚。
4. 完成后，设置页的 GET 和 POST 都拒绝再次初始化。

在初始化完成前，除健康检查、必要静态资源和设置流程外，其他页面与接口均不可用，避免在管理员建立前产生无人审批的注册申请。

### 6.2 注册与审批

1. 登录页提供“立即注册”。
2. 注册必填用户名、密码、确认密码、真实姓名和部门。
3. 新记录为 `pending`，不能创建会话。
4. 管理员批准后状态变为 `active`。
5. 管理员拒绝后删除申请，申请人需要重新注册。

### 6.3 登录和单会话

- 密码长度为 8–128 个字符，使用 Python 标准库 `hashlib.scrypt` 和每用户随机盐。
- 成功登录后将 `UserService.authenticate()` 返回的 `User` 快照传给 `SessionService.issue(authenticated_user)`，生成至少 256 位随机令牌，原始值只放入 Cookie。
- Cookie 设置 `HttpOnly`、`SameSite=Lax` 和 `Path=/`；HTTPS 环境通过配置增加 `Secure`。
- 会话有效期为绝对 7 天，不因活动而无限延长。
- 新登录在事务中替换该账号的旧会话。旧设备的下一个受保护请求返回会话失效并跳转登录。
- `pending` 和 `disabled` 账号均不能登录。停用操作立即删除现有会话。
- 登录失败按用户名和来源地址进行短时限速。

### 6.4 密码修改和重置

- 用户修改自己密码时需要提供旧密码。成功后撤销会话并要求重新登录。
- 管理员不能查看现有密码，只能创建随机临时密码。
- 重置后设置 `must_change_password`，并立即撤销该用户会话。
- 使用临时密码登录后，除修改密码和退出外，其他受保护页面与 API 都不可访问。

### 6.5 CSRF 和输入验证

- 已登录修改类请求使用会话绑定 CSRF 令牌，并使用恒定时间比较。
- 设置、登录和注册页使用服务端签名的匿名 CSRF 令牌。
- 服务端验证字段长度、类型和枚举，不依赖 HTML 表单的 `required` 或 JavaScript。
- 报销日期和 11 行行程日期均允许留空，保持当前产品行为。

## 7. 报销生成与个人历史

### 7.1 生成

1. 仅 `active` 且不处于强制改密状态的普通用户可生成文件。
2. 服务端从当前账号读取姓名和部门，忽略客户端可能传入的对应值。
3. 每次请求创建随机记录 ID 和 `/data/tmp/<record_id>/` 临时目录。
4. Excel 生成成功后，LibreOffice 使用该记录独立的用户配置目录生成 PDF。
5. 只有 Excel 和 PDF 都通过校验后，才移动到正式目录并插入历史记录。
6. 任何步骤失败都不留下可见的残缺历史，并在能确认本次请求所有权时尽力清理临时文件。

跨平台 Python/POSIX 无法原子完成“创建目录并返回其文件描述符”。因此目录创建的失败原子性是尽最大努力：`mkdir` 后的首次 no-follow 身份检查必须成功，后续 `open`/`fstat` 必须与之匹配。如果首次检查失败或无法证明条目仍属于本次请求，系统不冒险删除，允许保留不入库、对用户不可见的 UUID 孤立目录。Task 8/13 的回收站清理和备份忽略这些未入库目录；未来只能按年龄人工或以同等身份校验安全清理。

并发生成数可配置，在 DS925+ 上默认为 2。超出时请求排队，不共享 LibreOffice 配置目录，不覆盖其他用户的文件。

### 7.2 历史和下载

- 普通用户只能列出 `user_id = current_user.id` 且 `deleted_at IS NULL` 的记录。
- Excel 使用附件下载；PDF 使用内联显示，前端在新标签页打开。
- 下载路由接收记录 ID 和文件类型，先用当前用户 ID 查询，不接收任意文件名或路径。
- 回收站中的记录不直接下载，需要先恢复。
- 管理员无论是否知道记录 ID，都无法通过应用列出或下载普通用户文件。

### 7.3 回收站

- 普通删除仅设置 `deleted_at`，不立即删除文件。
- 恢复仅允许所有者执行，并清空 `deleted_at`。
- 永久删除需要明确的二次确认标志，先校验归属和回收站状态，再删除文件和数据库记录。
- 服务启动时清理一次，之后每 24 小时清理 `deleted_at` 超过 30 天的记录。
- 如果文件删除只完成一部分，保留可重试的数据库状态并记录错误，不把部分失败报告为成功。

## 9. 界面设计

用户已选择左侧导航布局。

### 9.1 未登录页面

- 登录页：账号、密码、登录按钮和“立即注册”链接。
- 注册页：账号、密码、确认密码、真实姓名和部门。
- 设置页：只在系统尚未初始化时显示。

### 9.2 普通用户

- 左侧菜单：填写报销、历史记录、回收站。
- 左侧栏底部：当前姓名、部门、修改密码和退出。

- 历史表格显示生成时间、报销日期、显示名和操作。
- PDF 在新标签页打开；Excel 触发附件下载。
- 回收站显示剩余保留天数，提供恢复和永久删除。

### 9.3 管理员

- 左侧菜单：待审批、用户管理；待审批数量使用角标。
- 审批页显示账号、姓名、部门、申请时间和批准/拒绝操作。

在窄屏上，左侧栏收起为菜单按钮，不持续挤压报销表格。

## 10. HTTP 接口边界

具体路由名可在实施计划中与旧项目命名对齐，但必须覆盖以下边界：

- 公共：健康检查、初始化状态、登录页、注册页。
- 匿名写入：初始管理员、登录、注册；均需匿名 CSRF 校验和输入校验。
- 已登录通用：当前用户、退出、修改密码。
- 普通用户：生成报销、历史列表、文件下载、移入回收站、恢复和永久删除。
- 管理员：待审批列表、批准、拒绝、用户列表、档案更新、启停和密码重置。

页面隐藏按钮不视为权限控制。每个保护接口在进入业务逻辑前必须依次验证会话、账号状态、强制改密状态、角色和资源归属。
管理员的审批、编辑、启停和重置接口只能作用于 `role = user` 的目标，不能用普通用户管理接口修改初始管理员。

## 11. 错误处理与日志

- 页面和 API 返回可操作的中文错误，不暴露堆栈、SQL、本地路径或 LibreOffice 命令行。
- 每个请求使用请求 ID；日志记录时间、请求 ID、用户 ID、操作和结果。
- 日志不记录密码、临时密码、Cookie、会话令牌或完整报销表单。
- 生成失败时前端保留已填写数据，用户可修正或重试。
- 权限或归属检查失败时，资源接口使用统一的“无权限或记录不存在”响应，不向攻击者确认他人记录是否存在。

## 12. Docker 和群晖部署

目标为 Synology DS925+（AMD Ryzen V1500B，`x86_64`），只在局域网使用。

- 镜像目标平台为 `linux/amd64`。
- 基础镜像中安装 Python、LibreOffice 无界面转换组件和必要中文字体。
- 应用监听 `0.0.0.0:8800`，Compose 默认映射 `8800:8800`。
- 群晖挂载示例：`/volume1/docker/reimbursement/data:/data`。
- SQLite、随机会话/CSRF 签名密钥、用户文件和临时目录都位于 `/data`；密钥在第一次启动时创建，不写入镜像。
- 容器使用非 root 账号，部署文档说明群晖挂载目录所需权限。
- Compose 启用健康检查和 `restart: unless-stopped`。
- 本机开发使用相同的相对数据结构，通过环境变量替换根目录和 LibreOffice 可执行文件。

默认使用 HTTP，适合已确认的局域网范围。配置保留 HTTPS/Cookie Secure 开关，日后可放到群晖反向代理后，但不是首次部署必要条件。

### 12.1 备份和升级

交付包包含 Dockerfile、`compose.yaml`、配置示例、构建/导出脚本、备份脚本和中文群晖说明。

备份流程以一致性为优先：

1. 短暂停止应用容器，防止备份期间生成、删除或恢复。
2. 运行同一镜像的一次性备份命令，挂载原 `/data` 并用 SQLite backup API 生成一致性数据库副本。
3. 归档数据库副本、密钥和用户文件。
4. 重新启动容器并检查健康状态。

升级前必须先运行备份。替换镜像后保留原 `/data`。启动迁移失败时不启动 HTTP 服务，日志明确报告错误，以便使用备份回退。

## 13. 测试与验收

### 13.1 单元和服务测试

- `scrypt` 哈希与校验、密码长度和临时密码。
- 会话创建、单会话替换、过期、退出和撤销。
- 认证快照签发：`active`、`password_version` 和 `status_version` 在同一立即事务内校验；密码修改/重置及禁用后重新启用均不能让旧快照签发。
- CSRF 缺失、错误和正确请求。
- 初始设置仅一次、注册、批准、拒绝、停用和强制改密。
- 管理员重置密码后撤销会话。
- 档案修改仅影响新生成文件。

### 13.2 权限测试

对每个历史、下载、删除、恢复和永久删除接口，至少测试：

- 未登录。
- 所有者。
- 另一个普通用户。
- 管理员。
- 会话已被新登录替换。
- 账号已停用。

### 13.3 生成回归测试

- 使用已知表单数据生成 Excel，检查指定单元格值、公式、样式和打印设置。
- 确认报销日期和 11 行日期可留空。
- 确认附单据数量保持空白，不自动计算。
- 确认中文大写合计在 Excel 和 PDF 中一致。
- 用 PDF 页数、文字提取和渲染图像关键区域验证单元格未空白。
- 确认 PDF 顶部边距保持已调整结果。

### 13.4 并发和容器测试

- 两个用户同时生成，验证输出内容、所属目录和历史无交叉。
- 连续登录、审批和生成时不出现 SQLite 连接共享错误。
- 构建 `linux/amd64` 镜像，检查 LibreOffice 和中文字体。
- 运行首次设置、注册审批、生成下载、容器重启和持久化验收。

## 14. 交付标准

功能完成需要同时满足：

- 新项目不修改旧工作版本。
- 上述认证、审批、用户管理、个人历史和回收站流程均通过自动化测试。
- 任意用户和管理员均无法通过应用下载他人文件。
- 现有 Excel/PDF 结果通过回归和视觉检查。
- Mac 本机可运行调试，群晖 DS925+ 可通过默认 8800 端口启动。
- 重启或更换容器后，用户、历史、文件和密钥保持不变。
- 交付完整 Docker 包、备份工具和中文部署文档。
