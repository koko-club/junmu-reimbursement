# 在线报销系统：统一页面标题与标签栏图标设计

## 背景与目标

当前各页面使用各自的浏览器页面标题，回收站还会在脚本运行时动态改为“回收站”。本次改动将所有可访问 HTML 页面以及备用 HTML 生成器的浏览器标签标题统一为“在线报销系统”，并使用用户提供的 PNG 作为浏览器标签栏 favicon。页面左侧现有“君牧在线报销系统”品牌图和文字保持不变。

## 范围

- 覆盖初始化、登录、注册、修改密码、填写报销、报销记录、回收站和系统管理页面。
- 覆盖 `history.js` 对回收站标题的运行时覆盖。
- 覆盖 `web.py` 的备用 HTML 生成器，避免未来错误页或内部调用恢复旧标题。
- 将用户提供的图片原样保存为 `static/favicon.png`，沿用现有静态文件安全与 MIME 类型处理。
- 不改变页面内品牌资源、导航文案、路由、认证逻辑或业务行为。

## 实现方案

每个服务端模板的 `<head>` 明确包含：

```html
<title>在线报销系统</title>
<link rel="icon" type="image/png" href="/static/favicon.png">
```

`static/history.js` 在回收站作用域中不再设置“回收站”作为 `document.title`，而是保持“在线报销系统”。`WebApplication._page_markup` 生成的备用文档也输出相同标题和 favicon 链接。favicon 文件不替换现有 `static/logo.png`。

## 验收与测试

1. 前端契约测试遍历全部七个模板，确认标题精确为“在线报销系统”、favicon 链接和 PNG 资源路径存在。
2. 前端契约测试确认历史脚本不会把标签标题改为“回收站”。
3. 静态资源检查确认 `static/favicon.png` 是有效 PNG，且服务端请求返回 `Content-Type: image/png`。
4. 运行现有前端/服务端测试，确保认证、路由和静态文件安全行为没有回归。
5. 在实际 HTTP 响应中检查未初始化页面和已认证页面的 `<title>` 与 favicon 链接；回收站脚本执行后标题仍为“在线报销系统”。

## 非目标与风险

- 不生成或裁剪新的图形，不替换页面侧栏 logo。
- 浏览器可能按 favicon 规范缩放用户提供的非标准比例图片；这是原图作为 favicon 的预期浏览器行为，不影响资源可用性。
- 浏览器 favicon 缓存可能使旧图标暂时显示；资源路径固定，验证时可通过无缓存请求或重新加载确认服务端内容。
