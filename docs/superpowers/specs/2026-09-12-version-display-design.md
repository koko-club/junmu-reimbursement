# 版本信息显示设计

## 目标

将项目版本号提升为 `v1.0.2`，并在所有登录后页面侧栏的“当前登录”信息下显示当前版本。页面显示值必须读取项目统一版本源，不在模板或前端脚本中硬编码具体版本号。

## 现状与约束

- 项目根目录 `VERSION` 文件是发布版本号的现有统一来源，当前值为 `v1.0.1`。
- 登录后侧栏存在于 `index.html`、`history.html` 和 `admin.html`，三者均包含 `id="current-user"`。
- 首页当前由 `_root` 直接读取并返回模板文件；历史记录、回收站、管理员页及修改密码页经过 `_template_page` 做 CSRF/页面占位符替换。
- 页面版本文案应与当前登录信息保持同一侧栏账户区域内，格式为 `版本：<VERSION>`。

## 方案

后端在应用初始化时读取项目根目录的 `VERSION` 文件并保存规范化版本字符串。模板渲染统一通过 `_template_page` 注入版本值，将模板中的版本占位符替换为 HTML 转义后的实际版本；首页 `_root` 改为走同一渲染路径，确保所有登录后页面使用相同来源。三个侧栏模板在“当前登录”块后增加独立的版本元素，例如：

```html
<div class="sidebar-version">版本：<span id="app-version">__APP_VERSION__</span></div>
```

读取失败时页面按现有模板不可用错误处理返回 500，不回退到硬编码版本号。

## 测试与验收

- `VERSION` 内容为单行 `v1.0.2`。
- 三个登录后侧栏均包含版本占位符和 `版本：` 文案。
- 模板渲染测试验证占位符会被 `VERSION` 实际内容替换，且输出不会残留占位符。
- 运行前端契约测试及与 Web 路由/模板相关的测试，确认既有 CSRF、登录和页面路由行为不受影响。
